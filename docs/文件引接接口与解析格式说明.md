# 文件引接接口与 CSV/XML 解析格式说明

> 适用后端：`backend/src/main/java/com/gx/etl/receive/`
> 核心代码：[YjExecController.java](../backend/src/main/java/com/gx/etl/receive/controller/YjExecController.java)、[YjExecService.java](../backend/src/main/java/com/gx/etl/receive/service/YjExecService.java)

## 1. 接口说明：`/api/yj/exec/file/exec`

**该接口是存在的**，不要被"报错/404"误导。完整路径为：

```
POST http://127.0.0.1:8689/api/yj/exec/file/exec
```

- 类注解：`@RestController @RequestMapping("/api/yj/exec")`
- 方法注解：`@PostMapping("/file/exec")`
- 请求体（Body）：**JSON 数组**，每个元素是一条文件引接配置，格式如下：

```json
[
  {
    "id": 1,
    "batchNum": "PC20260828120000_ABC123",
    "createBy": "admin"
  }
]
```

| 字段 | 必填 | 说明 |
|------|------|------|
| `id` | 是 | 文件引接配置 ID（对应 `T_YJ_FILE_CONFIG` 主键；兼容写法 `configId`） |
| `batchNum` | 否 | 批次号，不传则自动生成 |
| `createBy` | 否 | 操作人，默认 `admin` |

**响应示例**：

```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "result": "引接成功，10条数据",
    "success": true
  }
}
```

> 若调用报错，请确认：① 后端服务已启动在 8689 端口；② 请求方法是 POST；③ Content-Type 是 `application/json`；④ body 是数组而非单个对象。

## 2. 处理流程

1. 根据 `id` 加载 `T_YJ_FILE_CONFIG` 配置，取 `filePath`（服务器上的文件绝对路径）。
2. 若配置了 `analysisProtocolId`，加载 `T_YJ_PROTOCOL` 解析协议。
3. 根据协议 `fileType` 决定解析方式：
   - `XML`（不区分大小写）→ 走 **XML 解析**；
   - 其他（TXT/CSV/DAT/默认）→ 走 **文本解析**。
4. 解析结果按行写入目标数据源（先清空目标表，再批量插入）。

## 3. CSV / 文本解析格式

**适用范围**：协议 `fileType` 不是 `XML` 的所有文本文件（TXT、CSV、DAT 等）。

**解析规则**（见 `parseTextFile`）：

| 规则 | 说明 |
|------|------|
| 分隔符 | 取协议的 `separator` 字段，**默认为制表符 `\t`**；分隔符会被 `Pattern.quote()` 转义，逗号/分号/竖线等均可 |
| 跳行 | 取配置 `jumpRow`（如 `"1,2"` 表示跳过第 1、2 行） |
| 空行 | 自动跳过 |
| 字段处理 | 每行按分隔符 `split(regex, -1)` 拆分，每格 `trim()`（首尾去空白） |
| 表头 | **不会**被自动识别，解析结果中的每一行都按数据行入库 |

### 3.1 分隔符为制表符（默认）

```
1001	张三	M	1990-01-01
1002	李四	F	1992-02-02
1003	王五	M	1995-03-03
```

### 3.2 分隔符为逗号（协议 `separator = ","`）

```csv
1001,张三,M,1990-01-01
1002,李四,F,1992-02-02
```

### 3.3 带跳行（配置 `jumpRow = "1"`）

```
# 这是注释行，会被跳过
1001	张三	M	1990-01-01
1002	李四	F	1992-02-02
```

> **注意**：如果你希望表头行入库，CSV 里就放表头行，程序会原样写入；如果你不希望表头入库，用 `jumpRow` 跳过它。

## 4. XML 解析格式

**适用范围**：协议 `fileType = "XML"`。

**解析规则**（见 `parseXmlFile`）：

1. 用 DOM 解析整个 XML 文件。
2. 通过 `getElementsByTagName("record")` 查找**所有 `<record>` 节点**（无论根节点叫什么名字）。
3. 每个 `<record>` 下的**直接子元素**即为一个字段：子元素标签名 = 列名，文本内容 = 值。
4. **第一个 `<record>` 的字段名会被当作第 1 行数据写入**（即表头也入库，共 1 行）；后续每个 record 为 1 行数据。

### 4.1 标准 XML 示例

```xml
<?xml version="1.0" encoding="UTF-8"?>
<data>
    <record>
        <id>1001</id>
        <name>张三</name>
        <sex>M</sex>
        <birthday>1990-01-01</birthday>
    </record>
    <record>
        <id>1002</id>
        <name>李四</name>
        <sex>F</sex>
        <birthday>1992-02-02</birthday>
    </record>
    <record>
        <id>1003</id>
        <name>王五</name>
        <sex>M</sex>
        <birthday>1995-03-03</birthday>
    </record>
</data>
```

解析结果等价于（第 1 行是字段名，会入库）：

```
id      name     sex  birthday
1001    张三      M    1990-01-01
1002    李四      F    1992-02-02
1003    王五      M    1995-03-03
```

### 4.2 注意事项

- 标签名**必须**是 `<record>`（大小写敏感），根节点名称随意（上面用 `<data>`，`<root>`、`<xml>` 均可）。
- 字段取的是 `<record>` 的**直接子元素**，嵌套的子元素、属性（如 `<id code="1">`）会被忽略。
- 文本内容会 `trim()`。
- 若配置了协议列定义（见第 5 节），表头行的字段名顺序需与列定义顺序一致，否则入库列会错位。

## 5. 解析协议（`T_YJ_PROTOCOL`）字段说明

| 字段 | 作用 |
|------|------|
| `fileType` | 文件类型，`XML` 走 XML 解析，其他走文本解析 |
| `separator` | 文本文件分隔符，默认 `\t` |
| `tableName` | 目标表名；不配则取文件名（去扩展名，超 30 字符截断） |
| `jsonForm` | 列定义，JSON 数组。每项含 `columnName`（列名）、`columnIndex`（排序号，决定建表列顺序）。配置了它，建表用这些列名、`INSERT` 按此顺序位置对应 |
| `idColumnName` | 主键列（当前 `execFile` 流程未使用，仅保留字段） |

**列定义示例**（`jsonForm`）：

```json
[
  {"columnIndex": 1, "columnName": "id"},
  {"columnIndex": 2, "columnName": "name"},
  {"columnIndex": 3, "columnName": "sex"},
  {"columnIndex": 4, "columnName": "birthday"}
]
```

**表结构创建规则**：目标表不存在时自动建表，所有列一律 `VARCHAR(2000)`；表已存在则先 `DELETE` 清空再插入。

## 6. 配置入库（T_YJ_FILE_CONFIG）

| 字段 | 作用 |
|------|------|
| `filePath` | 待解析文件的**服务器绝对路径**（必填，文件必须已上传到该路径） |
| `analysisProtocolId` | 关联的解析协议 ID（可选） |
| `targetDataSourceId` | 目标数据源 ID（必填） |
| `targetSchema` | 目标 schema（MySQL 可空） |
| `jumpRow` | 跳过的行号，逗号分隔，如 `"1,2"` |

## 7. 常见报错排查

| 现象 | 原因/处理 |
|------|-----------|
| 404 / 接口不存在 | 后端未启动，或请求方法/路径不对；路径是 `POST /api/yj/exec/file/exec` |
| 文件内容为空 | 文件不存在、未上传到 `filePath`，或解析后 0 行 |
| XML 解析 0 行 | 文件里没有 `<record>` 标签 |
| 列错位 | CSV 字段顺序与协议 `jsonForm` 列定义顺序不一致 |
| 表头被写入数据 | CSV/文本不会自动过滤表头，XML 会把第 1 个 record 的字段名当数据写入；需跳行或接受该行为 |
