# 处理流程设计（ETL Pipeline Editor）功能说明

## 1. 架构概述

可视化 ETL 流程编辑器，类似 Kettle/Pentaho Data Integrator。用户从左侧拖拽算子到 jsPlumb 画布，连线组成 DAG，配置各节点后执行。前端 Vue 2 + jsPlumb 负责可视化编辑，后端 Spring Boot 负责 DAG 执行、算子调度和持久化。

### 界面布局（四面板）

```
┌──────────┬────────────────────────┬──────────┐
│  左侧栏   │      画布 (jsPlumb)     │  右侧栏   │
│ Components│      #mainContainer    │   Attr   │
│   Tree    │                        │          │
├──────────┴────────────────────────┴──────────┤
│              底部面板 (Terminal)               │
│         步骤度量 | 日志 | 批量进度              │
└──────────────────────────────────────────────┘
```

```javascript
  data: {
    pluginId: "TableInput",     // 算子类型
    text: "表输入",              // 显示名
    icon: "ui/images/xxx.svg?...",

    tableData: [{ tableChartsName: "col1", name: "streamCol1" }],

  }
}
```

### 4.4 DAG 执行引擎

**文件：** `backend/src/main/java/com/gx/etl/flow/service/FlowExecutionEngine.java`

**`execute(flowJson, nodeId, params)` 执行流程：**

1. `DagParser.parse(flowJson)` 解析为 `Map<String, FlowChartNode>`
2. `DagParser.topologicalSort()` 获取拓扑执行顺序
3. 按顺序遍历节点：
   - 从 `OperatorRegistry.getOperator(pluginId)` 获取算子
   - 合并上游输出 DataSet（单上游直接传递，多上游拼接）
   - 如需要则物化输入（Sort、Join 等）
   - 构建 `OperatorContext`（含 `_tableData` 字段映射）
   - 执行 `${key}` 参数替换
   - 调用 `operator.execute(ctx, input)`
   - 记录步骤指标
4. 返回 `ExecutionResult`：success、dataSet、totalRows、log、stepMetrics、stepStatusList

### 4.5 DAG 解析器

**文件：** `backend/src/main/java/com/gx/etl/flow/service/DagParser.java`

- `parse(flowJson)`：解析 JSON 为 FlowChartNode 对象，通过端点 UUID 映射建立上下游关系
- `topologicalSort(nodeMap)`：DFS 拓扑排序，含环检测

### 4.6 算子注册中心

**文件：** `backend/src/main/java/com/gx/etl/operator/core/OperatorRegistry.java`

通过 Spring 注入自动发现所有 `@Component` 标注的 `AbstractOperator` 子类，`@PostConstruct` 时按 `getId()` 注册。未匹配的 pluginId 返回 `GenericPassThroughOperator`（直通）。

### 4.7 抽象算子基类

**文件：** `backend/src/main/java/com/gx/etl/operator/core/AbstractOperator.java`

| 抽象方法 | 说明 |
|----------|------|
| `getId()` | 唯一 ID，对应前端 pluginId |
| `getName()` | 中文显示名 |
| `getCategory()` | 分类：input/output/transform/script |
| `getSchema()` | 前端表单生成的 OperatorSchema |
| `execute(OperatorContext ctx, DataSet input)` | 执行逻辑 |
| `requiresMaterializedInput()` | 是否需要物化输入（Sort/Join/Unique 为 true） |

### 4.8 目标表输出算子

**文件：** `backend/src/main/java/com/gx/etl/operator/output/BoundTableOutputOperator.java`

`@Component`，`getId() = "BoundTableOutput"`，`getName() = "目标表输出"`

**execute 逻辑：**
1. 从 config 获取 `boundTable`
2. 从 context 获取 `_tableData`（字段映射）
3. 构建目标列和源列的映射关系
4. 如无映射则按位置自动匹配
5. 可选 truncate 清空目标表
6. 构建 INSERT SQL，批量执行（默认 1000 条提交）
7. 返回 `DataSet.empty()`（汇算子）

### 4.9 核心数据结构

**DataSet** (`operator/core/DataSet.java`)：`Iterable<DataRow>`，支持流式和批量模式。方法：`collect()`、`count()`、`filter()`、`isEmpty()`、`getColumnNames()`

**OperatorContext** (`operator/core/OperatorContext.java`)：包装 config 和数据源。提供 `getString`、`getInt`、`getBoolean`、`getDataSource(id)` 等方法。

**FlowChartNode** (`flow/service/FlowChartNode.java`)：字段 `id`、`pluginId`、`name`、`config`(Map)、`tableData`(List)、`upstreamIds`、`downstreamIds`

## 6. 核心概念

### 6.1 jsPlumb 画布

- **添加节点：** 侧边栏拖拽 → `ev.dataTransfer.setData('target', JSON.stringify(data))` → 画布 drop → `FlowChart.addNode()` → 创建 DOM + Vue Node 组件 + jsPlumb 端点
- **连线：** jsPlumb `connection` 事件 → 存储为 `"sourceEndpointUUID&&targetEndpointUUID"`
- **数据流：** `model.js` 为单一数据源，`getData()` 返回完整 JSON，`loadData()` 恢复画布
- **缩放平移：** `FlowChart/moveAndZoom.js` 使用 jsPlumb pan/zoom API

### 6.2 算子注册与发现

- **前端：** `TaskTypeConfig/*/index.js`（70+ 文件）定义表单配置，`require.context` 启动时加载
- **后端侧边栏：** 从 `T_OPERATOR_CATEGORY` + `T_OPERATOR_TYPE` 数据库表加载
- **后端执行：** `OperatorRegistry` 通过 Spring DI 自动发现 `@Component` 标注的 `AbstractOperator` 子类

### 6.3 DAG 执行引擎

1. `DagParser.parse()` 解析 JSON → `FlowChartNode` 对象
2. `topologicalSort()` DFS 拓扑排序 + 环检测
3. 按拓扑序执行，每个节点接收上游 DataSet：
   - 无上游 → `DataSet.empty()`
   - 单上游 → 直接传递
   - 多上游 → 拼接（默认合并策略）
4. 参数替换：执行前将 config 中的 `${key}` 替换为实际参数值

### 6.4 绑定表功能

**流程级绑定：**
- 工具栏"绑定表"按钮 → 弹框选择表 → 逗号分隔存入 `T_TRANSFORMATION.BIND_TABLE_NAMES`

**左侧栏展示：**
- 监听 `bindTableNames` → 调 `API.getBindTableColumns` 获取字段（含注释）
- 底部"目标表字段"区域，按表分组，可折叠

**右侧栏映射（BoundTableOutput 节点）：**
- 目标表下拉 + 目标字段列表 + 流字段下拉（可搜索）
- 映射保存为 `[{tableChartsName: "目标列", name: "流字段"}]`

**后端执行：**
- `BoundTableOutputOperator` 读取 `_tableData` 构建 INSERT SQL，批量写入

### 6.5 流程 JSON 数据格式

```json
{
  "nodes": [{
    "id": "node-uuid",
    "points": { "targets": ["target-uuid"], "sources": ["source-uuid"] },
    "position": { "left": 100, "top": 200 },
    "data": { "pluginId": "TableInput", "text": "表输入", "icon": "...", "nodeId": "node-uuid" },
    "properties": {
      "ruleForm": { "stepName": "表输入", "sql": "...", "connection": "..." },
      "tableData": [{ "tableChartsName": "col1", "name": "streamCol1" }],
      "tabList": []
    }
  }],
  "endpoints": [{ "id": "target-uuid", "data": { "value": "输入" } }],
  "edges": ["source-uuid&&target-uuid"],
  "head": ""
}
```

### 6.6 执行模式

**单次执行：**
1. 保存流程 → 调 `/run.do` → 返回 success/rowCount
2. 轮询 `/result.do` 获取日志和步骤指标
3. 节点上显示成功/失败状态

**参数执行：**
1. 提取 `${xxx}` 变量 → 动态生成参数输入表
2. 单行：调 `execModel` 带 params
3. 多行：调 `/batchRun`

**批量执行：**
1. 调 `/batchRun` 返回 taskId
2. WebSocket `ws://<host>/ws/batchProgress/<taskId>` 接收实时进度
3. 后端线程池并行执行（默认 5 并发）
4. 前端更新"批量进度"Tab：进度条、统计、批次详情
5. 支持取消：调 `/cancelBatch`
