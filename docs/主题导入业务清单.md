# 主题与采集配置 - 业务问题清单

## 一、业务背景

系统从 MySQL 模型库（modelmanager）获取主题和字段结构，导入到达梦数据库（ETL）的主题配置表中，用于后续仿真数据的引接处理。

### 核心数据模型（MySQL modelmanager）

```
topic (name=主题名, type=类型标识, remark=中文备注)
  ↓ topic.type = simulatmutual.name
simulatmutual (id=, name=)
  ↓ simulatmutual.id = dataitem.simulatmutual_id
dataitem (simulatmutual_id, name=字段技术名, meaning=中文含义, type=数据类型, instruction_type=字段类型, compdata_id=复合数据ID)
```

### instruction_type 字段说明

- **simpleType**：基础数据，直接使用 dataitem 的 name/meaning/type
- **complexType**：对象/嵌套结构，需要通过 compdataitem 表展开子字段

### complexType 展开逻辑

```
dataitem.instruction_type = 'complexType'
  → dataitem.type 的值（如 "messageData"）
  → compdataitem WHERE type = "messageData" → 得到 id（如 1）
  → dataitem WHERE compdata_id = 1 → 得到子字段（如 ptId/平台id, ptType/平台类型）
```

### 当前已有数据验证（MySQL）

```
dataitem 关系：
- simulatmutual_id=1 → HIT 主题字段：weaponUID(弹id), isHit(是否命中), column3(属性3)
- simulatmutual_id=2 → ATTACK 主题字段：platformUID, platformType, missileUID, missileType, time
- simulatmutual_id=9 → YJ18BTrajectoryData 主题字段：simTime, missileUID, longitude, latitude, altitude, vx, vy, vz, game, theta, psi, phase 等
- simulatmutual_id=11 → TEST 主题字段：type(simpleType), messageData(complexType)

complexType 展开验证：
compdataitem: id=1, type=messageData
dataitem WHERE compdata_id=1 → ptType(平台类型), ptId(平台id)
```
