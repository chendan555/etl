## 仿真方案引接处理实现

### 数据流
```
Scheme.cjListId → CjConfig.id → CjConfig.ybList（逗号分隔主题ID列表）
  → T_TOPIC_CONFIG（TOPIC_NAME/TOPIC_CODE/TABLE_NAME）
  → T_TOPIC_FIELD（排序字段列表）

SchemeDetail.ybList（逗号分隔的实例ID，即 deduce_task_id）
  → MySQL data_collect.t* 表（topic=TOPIC_CODE, id=实例ID）
  → msgpack 解包 msg_info
  → 按 T_TOPIC_FIELD 顺序映射列值
  → INSERT INTO 达梦 TABLE_NAME (SCHEME_ID, 字段1, 字段2, ...) VALUES (实例ID, 值1, 值2, ...)
```

### 后端改动

**1. pom.xml — 加 msgpack-core 依赖**
```xml
<dependency>
    <groupId>org.msgpack</groupId>
    <artifactId>msgpack-core</artifactId>
    <version>0.8.20</version>
</dependency>
```

**2. SchemeProcessService — 实现真正的引接逻辑**

`processScheme` 方法替换为：

对每个 status=0 的 SchemeDetail：
1. 从 Scheme.cjListId → CjConfig.ybList 取逗号分隔的主题 ID
2. 用 TopicConfigMapper.selectBatchIds 查出 TopicConfig 列表（含 tableName、topicCode）
3. 对每个 TopicConfig，用 TopicFieldMapper 按 topicId+sortOrder 查出字段列表
4. 用 ybList（逗号分隔的实例ID）对每个实例ID：
   - 连 MySQL data_collect，查 `SELECT id, topic, msg_info FROM t* WHERE id = ? AND topic = ?`
   - tryUnpack(msg_info) 解包 msgpack → List<Value>
   - 按 T_TOPIC_FIELD 字段顺序，从 List<Value> 里按位置取值映射到列名
   - INSERT INTO 达梦 TABLE_NAME (SCHEME_ID, fieldName1, fieldName2, ...) VALUES (实例ID, 值1, 值2, ...)
5. 标记 SchemeDetail.status=1

**3. tryUnpack 方法** — 从 DataCollectWeb 移植核心逻辑：
- 读 msg_info 为 byte[]
- 用 msgpack-core 的 MessagePack.newDefaultUnpacker 解包
- 返回 Object（数字/字符串/数组）
- 失败时回退用 ISO-8859-1 还原字节再解包

**4. MySQL 连接** — 复用 DynamicDataSourceManager：
- 用 DatabaseSourceMapper 查 id=2 的 MySQL 数据源
- 连 data_collect 库（通过 schema 参数指定）
