# PRD: 批量执行进度显示

## Problem Statement

作为 ETL 流程设计平台的用户，当执行批量任务（可能包含几百次执行）时，我无法实时看到执行进度。当前的实现是同步执行所有批次后才返回结果，导致：
- 用户需要长时间等待，不知道执行到哪一步
- 如果某一批次失败，无法及时发现
- 无法在执行过程中取消任务
- 用户体验差，特别是执行几百次时可能需要等待几分钟甚至更久

## Solution

实现 WebSocket 实时推送的批量执行进度显示功能。在流程设计页面的底部面板新增"批量进度" Tab，实时显示：
- 整体进度条和百分比
- 成功/失败/耗时统计
- 可展开的每批次详情表格
- 支持取消正在执行的批量任务

## User Stories

1. As an ETL 开发者，我想要在批量执行时看到实时进度条， so that 我可以知道任务执行到哪一步了
2. As an ETL 开发者，我想要看到已成功和失败的批次数量， so that 我可以快速了解执行状况
3. As an ETL 开发者，我想要看到已用时间和预计剩余时间， so that 我可以合理安排工作
4. As an ETL 开发者，我想要展开查看每批次的详细信息（参数、状态、耗时、影响行数）， so that 我可以定位具体哪批数据出了问题
5. As an ETL 开发者，我想要在发现异常时取消正在执行的批量任务， so that 我可以避免继续执行错误的批次
6. As an ETL 开发者，我想要在某批次失败时看到具体的错误信息， so that 我可以快速定位问题原因
7. As an ETL 开发者，我想要在下次执行时自动清空旧的进度日志， so that 我不会混淆不同次执行的结果
8. As an ETL 开发者，我想要在执行完成后查看完整的执行统计， so that 我可以评估本次批量执行的效果
9. As an ETL 开发者，我想要在 WebSocket 连接断开时收到提示， so that 我知道需要刷新页面重新连接
10. As an ETL 开发者，我想要在批量执行时不影响流程设计的其他操作， so that 我可以继续编辑其他流程
11. As an ETL 开发者，我想要看到每批次处理的行数统计， so that 我可以了解数据处理量
12. As an ETL 开发者，我想要在进度表格中看到每批次使用的参数值， so that 我可以知道是哪组参数导致了问题
13. As an ETL 开发者，我想要在执行完成后看到总处理行数， so that 我可以评估整体数据处理效果
14. As an ETL 开发者，我想要在进度表格中看到批次执行速度（批次/秒）， so that 我可以预估剩余时间
15. As an ETL 开发者，我想要在批量执行开始时看到总批次数量， so that 我可以预估任务规模

## Implementation Decisions

### 通信方式
- 使用原生 WebSocket（而非 STOMP over WebSocket），因为场景简单，只需后端向前端推送进度
- WebSocket 在用户点击"执行"时建立连接，执行完成后可选择断开或保持
- 进入流程设计页面时不建立连接，避免资源浪费

### 后端改动
1. **FlowController.java**
   - 修改 `batchRun()` 方法为异步执行
   - 新增 WebSocket 端点 `/ws/batchProgress/{taskId}`
   - 使用 `@ServerEndpoint` 注解创建 WebSocket 处理类
   - 每完成一批次推送进度消息到前端
   - 支持取消标志位，循环中检查是否需要终止

2. **新增 BatchProgressWebSocket.java**
   - WebSocket 处理类，管理连接和消息推送
   - 维护 taskId 到 WebSocket session 的映射
   - 提供发送进度消息的方法
   - 处理连接关闭和异常情况

3. **进度消息格式**
   ```json
   {
     "taskId": "batch_12345",
     "current": 45,
     "total": 100,
     "successCount": 42,
     "failCount": 3,
     "elapsedTime": 150000,
     "estimatedRemaining": 190000,
     "totalRows": 15000,
     "status": "running|completed|cancelled",
     "batchDetails": [
       {
         "index": 1,
         "params": {"id": "1001"},
         "status": "success|fail",
         "elapsedTime": 1200,
         "rowCount": 150,
         "errorMsg": null
       }
     ]
   }
   ```

### 前端改动
1. **Terminal.vue**
   - 新增"批量进度" Tab
   - 显示进度条、成功/失败/耗时统计
   - 可展开的批次详情表格（使用 Element UI 的 el-table）
   - "取消"按钮
   - 进度表格列：批次、参数值、状态、耗时、影响行数、错误信息

2. **index.vue**
   - 批量执行时建立 WebSocket 连接
   - 接收进度消息并更新界面数据
   - 处理 WebSocket 连接断开和重连
   - 执行完成后保留日志直到下次执行

3. **api/index.ts**
   - 调整 `execBatchRun()` 返回方式，支持异步执行
   - 可能需要返回 taskId 用于 WebSocket 连接

### 失败处理策略
- 记录失败的批次信息（错误信息、参数值）
- 继续执行后续批次，不中断
- 在进度表格中用红色标记失败批次
- 最终统计中显示成功/失败数量

### 日志保留策略
- 保留本次执行的进度日志直到下次执行
- 下次点击"执行"时自动清空旧日志
- 不需要手动清除按钮

### 取消功能
- 提供"取消"按钮
- 后端维护取消标志位
- 循环中检查标志位，如果为 true 则终止执行
- 前端显示"已取消"状态

## Testing Decisions

### 测试原则
- 只测试外部行为，不测试实现细节
- 测试 WebSocket 消息的发送和接收
- 测试进度更新的准确性
- 测试取消功能的正确性

### 需要测试的模块
1. **BatchProgressWebSocket**
   - 测试 WebSocket 连接建立和断开
   - 测试消息发送和接收
   - 测试多个客户端连接的情况
   - 测试异常情况的处理

2. **FlowController.batchRun()**
   - 测试异步执行流程
   - 测试进度推送的准确性
   - 测试取消功能的正确性
   - 测试失败处理的逻辑

3. **Terminal.vue 批量进度 Tab**
   - 测试进度条显示
   - 测试统计信息更新
   - 测试批次详情表格
   - 测试取消按钮功能

### 测试优先级
- 优先测试核心功能：进度推送、取消功能
- 其次测试边界情况：网络断开、执行失败
- 最后测试用户体验：界面更新、动画效果

## Out of Scope

1. **暂停/继续功能** - 实现复杂，需要维护执行上下文，暂不支持
2. **执行历史记录** - 本次实现只保留当前执行的进度，不保存历史
3. **进度持久化** - 进度信息只在内存中，不保存到数据库
4. **多任务并行** - 暂不支持同时执行多个批量任务
5. **进度回调接口** - 暂不提供外部系统调用的进度查询接口

## Further Notes

### 性能考虑
- WebSocket 消息频率控制：每批次完成后推送一次，避免消息过多
- 批次详情表格使用虚拟滚动，支持几百条数据的流畅显示
- 进度条动画使用 CSS3，避免频繁的 DOM 操作

### 错误处理
- WebSocket 连接断开时提示用户刷新页面
- 后端执行异常时推送错误消息到前端
- 前端显示友好的错误提示，避免技术细节暴露

### 用户体验
- 进度条使用渐变色，视觉效果更好
- 成功/失败使用不同颜色标记（绿色/红色）
- 批次详情表格默认折叠，点击展开查看详情
- 执行完成后显示"执行完成"提示

### 后续优化方向
- 支持暂停/继续功能（需要更复杂的状态管理）
- 支持执行历史记录查看
- 支持进度持久化到数据库
- 支持多任务并行执行
